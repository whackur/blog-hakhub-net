청두의 CCTV 수백 대에서 모은 영상에는 한 사람의 움직임이 담겨 있었습니다. 앤트로픽의 2026년 9월 보고서에 따르면, 자료를 올린 사용자는 Moonshot의 Kimi를 쓰고 있다고 생각하며 이 인물의 행동이 평소와 다른지 물었습니다. 앤트로픽은 해당 요청이 Claude로 전달됐다고 주장합니다.

[Detecting and countering misuse of AI: September 2026](https://www-cdn.anthropic.com/e50be2e51e7695dc4b1366a37a245a597377d3b5/Anthropic-Detecting-and-countering-091026.pdf)는 Moonshot AI가 일부 고객 요청을 Kimi가 아닌 Claude로 전달하고 Claude의 응답을 Kimi 응답처럼 보여 줬다고 보고합니다. 앤트로픽은 이 보고서를 2026년 9월 10일 공개했습니다. CCTV 사례 외에도 중국 대형 국유기업 직원이 올린 내부 코드와 조사 당시 유효했던 접속 자격증명 사례를 담았습니다.

앤트로픽은 여러 캠페인을 탐지하고 차단했다고 설명합니다. 다만 보고서는 Moonshot의 우회가 정확히 언제 멈췄는지, 새 계정이나 다른 경로가 다시 만들어졌는지 밝히지 않습니다. 보고서 공개 자체가 모든 요청 경로를 끊었다고 단정할 근거도 없습니다.

## 보고서가 주장한 내용

보고서는 2025년 12월부터 2026년 8월까지 탐지하고 차단한 활동을 사이버 공격, 영향력 공작, 감시, 사기, 생물학, 재래식 무기, 무단 증류의 일곱 범주로 나눕니다. 이번 논란은 무단 증류 항목에 실렸습니다. 아래 내용은 앤트로픽의 자체 조사와 평가이며, 별도의 독립 조사 결과는 보고서에 포함되어 있지 않습니다.

Moonshot 사례(GTG-16002)에 대한 보고서의 주장은 이렇습니다. Moonshot이 고객 요청을 Kimi 대신 Claude로 전달하고 Claude의 응답을 사용자에게 보여 줬습니다. 한 사례에서 열흘 동안 요청 약 30만 건이 앤트로픽으로 중계됐고, 대부분 Claude Opus로 연결됐습니다. 앤트로픽은 proxy 서비스망에 위장 계정 5,380개가 쓰였으며, 계정 대부분이 싱가포르와 일본에 있는 것처럼 보였다고 적었습니다.

| 조직 | 보고서가 제시한 규모 |
|------|------|
| Moonshot (Kimi) | 2,300만 건 이상 교환. 열흘간 약 30만 건 중계, 위장 계정 5,380개 |
| Alibaba (Qwen/Tongyi Lab) | 1억 5,100만 건 이상. 앤트로픽이 측정한 최대 증류 캠페인 |
| Xiaomi (MiMo) | 1,500개 이상 계정에서 요청 40만 건 이상 |
| DeepSeek | Moonshot과 비슷한 중계 및 cross-session replay 전술 |

Moonshot과 Alibaba의 교환(exchange) 건수는 2026년 5월부터 7월까지 관측한 수치입니다. Xiaomi의 40만 건 이상은 3월과 4월 중 20일간 관측한 규모입니다. Moonshot의 열흘간 중계 수치에는 정확한 날짜가 붙어 있지 않습니다.

DeepSeek 사례(GTG-16001)에서 앤트로픽은 Claude Code, Agent SDK, OpenCode 같은 코딩 도구를 사용하는 고객의 요청을 골라 Claude Opus로 전달했다고 주장합니다. Xiaomi는 OpenClaw와 OpenCode를 통해 MiMo 이용자의 대화를 Claude에 재생했으며, 무료 MiMo-V2-Pro 체험이 끝날 무렵 증류 활동이 집중됐다고 보고서는 설명합니다. 즉, 보고서가 묘사한 대상은 무작위 요청 전체가 아니라 특정 종류의 작업과 대화입니다.

## 요청이 전달된 경로

일반적인 요청은 사용자가 Kimi 앱이나 API에 보내고, Moonshot의 서비스가 Kimi 모델로 처리한 뒤 결과를 돌려주는 흐름입니다. 앤트로픽 보고서가 주장한 경로에는 Claude API를 호출하는 중계 단계가 추가됩니다.

![앤트로픽 보고서의 주장에 따른 요청 경로 개념도입니다. 사용자의 요청이 Kimi 서비스에서 proxy 계정망을 거쳐 Claude로 전달되고, 응답이 다시 Kimi를 통해 사용자에게 돌아오는 흐름을 보여 줍니다.](/images/posts/anthropic-moonshot-disclosure-strategy/request-routing.svg)

*도식은 앤트로픽 보고서의 주장을 바탕으로 재구성한 개념도입니다. 보고서는 5,380개 계정과 열흘간 약 30만 건의 중계를 언급하지만, 정확한 라우팅 구현은 공개하지 않았습니다. [출처: 앤트로픽 보고서](https://www-cdn.anthropic.com/e50be2e51e7695dc4b1366a37a245a597377d3b5/Anthropic-Detecting-and-countering-091026.pdf)*

proxy는 요청을 대신 전달하는 중계 서버를 가리킵니다. residential proxy는 일반 가정용 인터넷 회선의 IP 주소를 출구로 사용합니다. 다만 앤트로픽은 Moonshot의 계정망에 residential proxy가 쓰였는지 구체적으로 밝히지 않았습니다. 보고서는 Alibaba의 첫 계정 풀이 5,000개에 가까웠고 residential proxy, 일회용 이메일, 가상 카드 결제 수단을 사용했다고 설명합니다. 첫 풀이 차단되자 두 번째 계정 풀로 옮겼으며, 일부 계정은 DeepSeek과 Xiaomi 요청도 중계했다고 합니다. 그 방식을 Moonshot에도 그대로 적용했다고 볼 근거는 없습니다.

보고서는 중국, 러시아, 이란을 서비스 미지원 국가의 예로 들고, 해당 지역에서 운영되는 계정 등 악용 징후가 있으면 신원 확인을 요구할 수 있다고 설명합니다. proxy의 겉보기 위치와 실제 요청자의 위치를 구분해야 하는 이유입니다. 이 일반 설명으로 Moonshot 계정의 실제 운영 위치까지 확정할 수는 없습니다.

앤트로픽은 요청이 단일 Moonshot 계정에서 들어온 것이 아니라 서로 달라 보이는 계정들을 통해 들어왔다고 설명합니다. 보고서가 확인했다고 밝힌 것은 Moonshot 사례의 위장 계정 5,380개와 겉으로 보이는 위치입니다. 실제 요청이 시작된 곳이나 계정을 나눈 정확한 방법까지 이 숫자만으로 알 수는 없습니다.

30만 건을 열흘로 나누면 하루 평균 3만 건입니다. 다시 계정 5,380개에 균등하게 나눈다면 계정당 하루 대여섯 건입니다. 이 계산은 규모를 감 잡기 위한 산술일 뿐이며, 실제 계정별 요청 분포를 보여 주지는 않습니다. 계정 생성, 결제, 중계 요청 운영에 상당한 작업이 필요하다는 점은 추정할 수 있지만, Moonshot의 구체적인 운영 절차는 보고서에 나오지 않습니다.

보고서는 다른 조직의 사례도 듭니다. MiniMax는 별도 회사를 세워 자체 proxy 서비스를 운영했고, 이 서비스는 앤트로픽과 OpenAI 모델만 제공하고 중국 모델은 취급하지 않았다고 합니다. SenseTime의 증류 과정에는 제3자 데이터 업체에서 구매한 대화 기록도 포함됐다고 서술합니다. 이런 사례는 계정망 차단만으로 모든 대화 유통 경로를 설명할 수 없다는 앤트로픽의 주장을 뒷받침합니다.

고객이 받은 응답의 품질이 Claude와 비슷했을 가능성은 보고서의 주장과 맞닿아 있습니다. 하지만 보고서는 Kimi의 벤치마크 점수가 이 중계로 만들어졌다고 주장하지 않습니다. 그 연결은 일부 Hacker News 이용자가 제기한 추측이며, 별도의 증거로 확인된 사실은 아닙니다.

## Thinking block과 cross-session replay

기술적으로 중요한 쟁점은 모델의 최종 답변뿐 아니라 추론 기록도 증류 자료로 수집했다는 앤트로픽의 주장입니다. 증류는 큰 모델의 출력을 학습 자료로 삼아 다른 모델의 능력을 끌어올리는 방법입니다. 이 보고서는 증류 자체보다 자료를 수집한 과정과 이용자 동의 여부를 문제 삼습니다.

Claude API 응답에는 thinking block과 signature 필드가 들어갈 수 있습니다. thinking 내용은 요약되거나 생략될 수 있으며, signature는 그 자체가 읽을 수 있는 추론문이 아닙니다. 보고서는 signature를 후속 API 호출에서 원래 추론 기록을 참조하는 값으로 설명합니다. 현재 API 문서는 이 필드에 암호화된 전체 추론이 담기며, 호출자가 해석하거나 파싱해서는 안 된다고 명시합니다. 보고서가 주장한 것은 암호를 직접 푼 과정이 아니라 Claude에 기록을 다시 출력하게 한 과정입니다. API 문서는 도구를 사용하는 대화에서 이전 block을 받은 그대로 돌려보내도록 안내합니다. 이런 일반적인 이어쓰기와 새 세션에서 저장된 signature를 다시 이용했다는 보고서의 주장은 구분해야 합니다.

앤트로픽은 Moonshot이 저장된 대화에서 signature를 보관한 뒤 새 세션에서 이를 재사용하고, Claude가 해당 추론을 다시 서술하도록 유도해 전체 chain-of-thought 기록을 추출했다고 주장합니다. 보고서는 Moonshot이 저장된 교환 외에 다른 경로로 수집한 추론 기록도 추출했다고 덧붙입니다. 보고서는 이를 cross-session replay라고 부릅니다. 이 설명은 API의 정상적인 이어쓰기와 다릅니다. 보고서에는 실제 요청 전문, 프롬프트, 코드, 맥락을 어떻게 바꿨는지 공개돼 있지 않습니다. 다음 그림의 맥락 변화는 보고서가 설명한 대응책을 바탕으로 한 개념적 재구성이지, 공개된 공격 절차가 아닙니다.

![Claude의 thinking block과 불투명한 signature, 정상적인 대화 이어쓰기, 앤트로픽이 주장한 새 세션 replay, 맥락 변화를 표현한 개념적 재구성, 보고서가 언급한 완화 조치를 구분한 그림입니다. 실제 요청과 맥락 변화는 공개되지 않았습니다.](/images/posts/anthropic-moonshot-disclosure-strategy/reasoning-replay.svg)

*정상적인 이어쓰기에서는 이전 thinking block을 같은 대화에서 그대로 전달합니다. 앤트로픽은 Moonshot이 signature를 저장한 뒤 새 세션에서 다시 사용해 Claude가 추론 기록을 출력하도록 유도했다고 주장합니다. 그림의 맥락 변화는 개념적 재구성이며, 보고서는 실제 요청과 변경 내용을 공개하지 않았습니다. [출처: 앤트로픽 보고서](https://www-cdn.anthropic.com/e50be2e51e7695dc4b1366a37a245a597377d3b5/Anthropic-Detecting-and-countering-091026.pdf), [Claude API thinking 문서](https://platform.claude.com/docs/en/about-claude/models/extended-thinking-models)*

최종 답변만 모으면 모델이 어떤 접근을 시도하고 수정했는지는 알기 어렵습니다. 추론 기록은 그 중간 과정을 학습 자료에 포함한다는 점에서 수집 동기가 다릅니다. 앤트로픽은 보고서에서 추론을 요약하면 다른 모델의 학습에 덜 유용해진다고 설명합니다. 그렇다고 요약본이 항상 시행착오를 전부 제외한다거나, 추론 기록이 있으면 원 모델의 능력을 그대로 복제한다고 단정할 수는 없습니다.

보고서가 소개한 완화 조치는 여러 층입니다. Claude는 응답 전에 추론을 요약해 내보내도록 바뀌었고, 앤트로픽은 Fable 5.1의 preserved thinking이 새 API 계정에서 추론 block 앞에 온 시스템 프롬프트, 도구 정의, 메시지를 바꾸지 못하게 한다고 설명합니다. 기존 block을 그대로 이어 쓰는 경우와 앞선 맥락을 바꿔 replay하는 경우를 구분해, 후자의 조작을 막으려는 조치입니다. 앤트로픽은 분류기 강화, 의심 계정 차단, 서비스 미지원 국가에서 운영되는 계정의 신원 확인도 함께 언급합니다.

## 보고서에 나온 민감 데이터

보고서는 PLA와 연계됐을 가능성이 높다고 평가한 사용자가 Kimi를 쓴다고 생각하며 청두 CCTV 자료를 올렸다고 설명합니다. 자료에는 한 사람을 추적한 영상과 PLA 시설, 중국전자과학기술그룹(CETC) 산하 연구기관, 국유기업 주변 카메라의 영상이 포함됐다고 합니다. 그 사용자는 추적 대상이 평소와 다르게 행동하는지 분석해 달라고 요청했습니다. PLA 연계 평가는 앤트로픽의 표현인 likely에 해당하며, 독립적으로 확인된 귀속은 아닙니다.

또 다른 사례에서는 중국 대형 국유기업의 엔지니어가 내부 시스템을 만들면서 여러 중국 기업의 내부 코드와 실사용 자격증명을 Kimi에 입력했다고 보고서는 주장합니다. 보고서가 이를 live credentials라고 부른 시점은 조사 당시입니다. 현재도 유효하다는 뜻은 아닙니다.

DeepSeek 사례에는 중국 기술 기업의 주요 AI 프로그램 사양과 조직 구조, 전략 목표가 포함됐다고 합니다. 러시아 국방기관이 사용하는 정부 데이터베이스의 실사용 자격증명도 보고서에 등장합니다. Xiaomi 사례에서는 수백 명의 사용자 이름과 연락처, 기업 자료가 열두 개 이상의 언어로 포함됐다고 설명합니다.

Moonshot이 고객에게 요청 중계 사실을 알렸는지 앤트로픽은 모른다고 밝혔습니다. 보고서에 근거해 모든 Moonshot 고객이 몰랐다고 단정할 수는 없습니다. DeepSeek에 대해서는 고객에게 알리지 않고 중계했을 가능성이 높다고 보고서가 별도로 평가합니다.

## 공개가 낳을 수 있는 효과

이 절부터는 제 해석입니다. 앤트로픽의 내부 의사결정 과정을 보고서만으로 확인할 수는 없습니다. 공개의 효과와 실제 동기는 구분해서 봐야 합니다.

### 차단과 공개는 다른 조치입니다

보고서는 2026년 2월 이후 무단 증류 캠페인을 탐지하고 차단했다고 설명합니다. Moonshot 관련 규모는 5월부터 7월까지 관측한 수치입니다. 보고서가 9월 10일 공개됐다는 사실만으로 중계 경로가 그날 종료됐다고 볼 수는 없습니다. 반대로 차단된 계정 외에 새 계정이나 다른 경로가 남아 있었다고 확인할 수도 없습니다. 보고서는 Moonshot 경로가 언제 중단됐는지 자세히 밝히지 않습니다.

따라서 공개 자체가 요청 경로를 끊었다고 보기보다, 앤트로픽이 차단 조치를 했다고 보고한 뒤 그 조사 내용을 공개했다고 정리하는 편이 정확합니다. 공개가 추가 우회 시도를 어렵게 만들 수는 있지만, 보고서는 그 효과를 측정한 자료를 내놓지 않았습니다.

### 이용자와 고객사의 확인 요구

요청이 Kimi에서 Claude로 넘어갔다면, 이용자와 기업 고객은 어디서 어떤 모델이 입력을 처리했는지 확인할 필요가 있습니다. 앤트로픽이 Moonshot의 통지 여부를 모른다고 밝혔기 때문에, 고객사는 자체 약관과 서비스 제공자의 설명을 확인해야 합니다. 공개 보고서는 Moonshot이 데이터 흐름과 고객 통지를 설명하도록 압박하는 효과를 낼 수 있습니다. 이것은 공개의 가능한 결과이지, 앤트로픽이 밝힌 내부 동기는 아닙니다.

기업 고객에게는 응답 품질과 데이터 처리 약속이 별개입니다. 국내 서비스를 선택한 이유가 데이터의 국내 처리였다면, 다른 국가의 사업자가 입력을 받았는지부터 확인해야 합니다. 특히 코딩 도구의 요청에는 저장소 구조, 코드 조각, 설정 정보가 함께 들어갈 수 있습니다. 요청 범위와 하위 처리 사업자를 확인하는 동안 구매나 갱신 검토가 길어질 수 있지만, 보고서가 실제 고객 이탈이나 매출 손실을 측정한 것은 아닙니다.

### 서비스 보호와 사업상 이해관계

앤트로픽은 Claude의 무단 사용을 탐지하면 요청을 막고 관련 계정을 차단한다고 설명합니다. 자사 모델 응답이 다른 모델의 학습에 쓰이는 일을 줄이는 것은 서비스 보호와 연결됩니다. Moonshot 고객의 입력이 Claude에 전달됐다는 주장까지 포함하면 데이터 처리와 고객 약속도 쟁점이 됩니다.

동시에 보고서 공개는 앤트로픽이 무단 사용을 찾아내고 대응할 수 있다는 점을 알립니다. frontier model 보호와 증류 위험에 관한 업계 논의에서 자사 주장을 뒷받침하는 자료로 활용될 수도 있습니다. 이것도 가능한 효과에 대한 해석이며, 보고서가 실제 결정 동기의 비중을 공개한 것은 아닙니다.

탐지한 중계를 계속 허용한다면 앤트로픽은 경쟁사 이용자의 질문에 Claude로 답하고, 그 응답이 다시 학습 자료로 쓰일 가능성도 감수해야 합니다. 관측된 2,300만 건을 모두 새 학습 사례로 볼 수는 없지만, 회사가 설명한 수집 규모를 고려하면 서비스 보호를 단순한 원칙 문제로만 보기는 어렵습니다. 추가로 얻을 조사 정보와 응답 제공 비용, 경쟁 모델에 쓰일 자료를 함께 따져야 합니다. 국가기관이 정보의 가치를 평가하는 상황과 모델 제공사가 자사 서비스 운영을 판단하는 상황은 이해관계가 다릅니다. 이 비교는 회사의 선택을 설명할 수 있는 분석이며, 실제로 그런 선택지를 검토했다는 증거는 아닙니다.

민감 데이터의 수신도 운영 부담을 만듭니다. 자격증명이 포함된 기록을 누가 열람할 수 있는지, 언제 삭제하는지, 사고 대응을 위해 무엇을 보존하는지 결정해야 합니다. 조사 중인 자료를 무조건 지우는 것도, 계속 쌓아 두는 것도 별도의 검토가 필요합니다. 원 보고서 서문은 적절한 경우 당국 및 업계 파트너와 정보를 공유했다고 밝히지만, 이것만으로 특정 정부기관과의 관계나 개별 자료의 전달을 추론할 수는 없습니다. 차단과 통지, 제한된 정보 공유, 공개 보고서는 각각 다른 조치이며, 공개가 법적으로 유일한 대응이었다는 근거는 없습니다.

### 개인정보와 규제 가능성

앤트로픽은 중국 AI 연구소들이 사용자 대화를 모델 학습에 이용한 방식이 개인정보 보호 법률과 서비스 약관에 어긋날 가능성이 높다고 평가합니다. 이 역시 앤트로픽의 법적 평가입니다. 구체적인 이용자 동의, 데이터 종류, 계약 조건, 적용 법률에 대한 조사 결과나 법원 판단은 보고서에 없습니다.

공개 보고서는 해당 연구소 소재국 규제당국이 사안을 검토하는 단서가 될 수 있습니다. 중국의 개인정보보호법은 개인 정보를 국외에 제공할 때 고지와 별도 동의 등 요건을 두며, 데이터안전법은 중요 데이터의 국외 제공을 별도로 규율합니다 ([개인정보보호법](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm), [데이터안전법](https://www.cac.gov.cn/2021-06/11/c_1624994566919140.htm)). 그러나 보고서만으로 특정 조항 위반이나 제재를 단정할 수는 없습니다. [AI타임스 보도](https://www.aitimes.com/news/articleView.html?idxno=215229)가 언급한 국가인터넷정보판공실(CAC)의 조사나 서비스 허가 취소 가능성도 추측입니다. 여기서 인용한 자료로는 실제 조사 개시를 확인할 수 없습니다.

### 탐지 방식과 안전장치의 공개

앤트로픽은 메타데이터와 비정상 활동 신호를 함께 분석해 proxy 계정망을 특정 조직과 연결하고, 개별 계정을 막는 데 그치지 않고 조직 단위로 대응한다고 설명합니다. 보고서 공개는 비슷한 운영을 준비하는 조직에 탐지 위험을 알릴 수 있습니다. 반면 외부에서는 귀속의 정확도를 확인할 자료가 부족합니다.

이런 대응이 반복되면 운영자는 계정과 결제 수단을 교체하고 요청 분산 방식을 조정해야 합니다. 앤트로픽도 새 우회 방식을 분석하고 탐지를 갱신해야 하므로 어느 쪽의 비용이 더 빨리 늘어나는지는 공개 자료로 계산할 수 없습니다. 다만 특정 조직의 활동이라고 지목하는 공개는 계정 차단 외에 고객 신뢰와 규제 대응 비용을 더할 수 있습니다. 귀속이 틀렸을 때의 피해도 커지는 만큼, 외부 검증에 필요한 근거가 얼마나 공개됐는지는 별도 쟁점입니다.

Zhipu 사례도 안전장치의 효과를 설명하는 근거로 보고서에 실렸습니다. 앤트로픽에 따르면 Zhipu는 Claude를 사후 학습 파이프라인 개선, 출력 평가, 추론 기록 정리에 이용했습니다. 이후 GLM 5.3을 준비하며 미국 프론티어 모델의 사이버 능력을 CTF 방식으로 시험했고, 일반에 제공되는 모델 중 사이버 안전장치를 강화했다고 소개한 Fable을 먼저 대상으로 삼았습니다. 앤트로픽은 Fable의 안전장치가 공격을 막자 Zhipu가 안전장치가 더 약하다고 판단한 Opus 4.6과 다른 연구소 모델로 옮겼다고 주장합니다. 이 내용도 앤트로픽의 조사 결과이며 독립 검증된 실험은 아닙니다.

이 사례는 안전장치가 실제 작업 선택에 영향을 줬다는 앤트로픽의 주장을 기업 고객에게 설명하는 데 쓰일 수 있습니다. 동시에 공격 시도가 사라졌다는 뜻은 아닙니다. 보고서의 설명대로라면 Zhipu는 다른 모델을 선택했습니다. 한 모델에서 시도를 어렵게 만든 효과와 업계 전체의 악용을 줄인 효과를 구분해야 하며, 보고서는 이후 활동 전체를 추적한 결과를 제시하지 않습니다.

### 정책 논의의 자료

CNBC는 보고서 발표 전인 9월 3일, 증류 공방과 온라인 계정 거래, 중국 모델에 대한 우려를 보도했습니다. 9월 10일에 나온 앤트로픽 보고서는 구체적인 숫자와 사례를 더해 미국의 frontier model 보호 논의에 인용될 수 있습니다.

Hacker News의 일부 이용자는 보고서를 규제 포획을 위한 로비 자료로 해석했습니다. 보고서가 정책 논의에 도움이 된다는 사실과 앤트로픽이 사업상 이해관계를 가진다는 사실은 함께 성립할 수 있습니다. 다만 공개 문서만으로 그 해석을 확정할 수는 없습니다.

## 앤트로픽의 설명과 독자의 판단

앤트로픽은 자사 서비스의 악의적 오용을 공개할 책임이 있다고 믿는다고 밝혔습니다. 이것이 회사가 공개한 이유입니다. 보고서는 동시에 자사 탐지와 대응 사례를 알리고, 무단 증류가 초래할 수 있는 위험을 설명합니다. 공개가 회사의 사업상 이해와 맞닿아 있을 가능성은 있지만, 어느 동기가 더 컸는지는 문서로 알 수 없습니다.

모델을 도입하는 조직에는 확인할 항목이 남습니다. 요청을 처리하는 하위 사업자, 국외 이전 조건, 로그 보존 기간, 모델 라우팅 방식, 고객 통지 절차를 계약과 운영 문서에서 확인해야 합니다. Kimi나 Claude에만 해당하는 점검은 아닙니다. 중간 서비스가 모델 요청을 전달하는 구조라면, 실제로 어느 서비스가 입력을 받는지 확인할 필요가 있습니다.

## 커뮤니티 반응

[보고서의 Hacker News 토론](https://news.ycombinator.com/item?id=49647300)과 [Moonshot 중계 사례 토론](https://news.ycombinator.com/item?id=49656698)에는 개인정보, 증류의 정당성, 기술적 개연성, 앤트로픽의 동기를 둘러싼 의견이 나왔습니다. 댓글은 이용자들의 관점이지, 보고서 내용을 검증하는 독립 조사 결과는 아닙니다.

앤트로픽의 데이터 처리 방식에 대한 우려가 컸습니다. CrzyLngPwd는 보고서를 “고객을 감시한다고 말하지 않으면서 고객을 감시한다고 말하는 방법”이라고 요약했습니다. qlte는 사례가 구체적이라 불편하고, 일부 이용자는 테러리스트라기보다 자기 일을 하는 연구자처럼 보인다고 했습니다. 구글이 이메일을 볼 수 있다는 사실과, 플래그된 계정의 받은편지함 내용을 공개적으로 상세히 설명하는 일은 다르다는 비유도 나왔습니다.

AlanYx는 조사에 대화 기록 보존이 필요했을 텐데, 탐지 대상 계정의 기록을 이용자에게 알리지 않고 보관한다면 일반 고객은 어떻게 안심할 수 있느냐고 물었습니다. Shank는 소비자 약관의 학습 이용 조항을 언급했습니다. wongarsu는 상용 약관과 zero data retention 계약이 더 엄격하다고 덧붙였고, 중계에 쓰인 수천 개 계정은 더 느슨한 소비자 약관을 따랐을 가능성이 있다고 추정했습니다. 다른 댓글에서는 어떤 모델이 응답할지 공개한 요금제와 Kimi를 내세우면서 Claude를 중계한 경우를 구분했습니다. 보고서는 앤트로픽의 탐지 역량을 설명하는 동시에 회사의 데이터 보관과 이용 정책에 대한 질문도 불러왔습니다.

증류를 둘러싼 윤리 논쟁에서는 미국 연구소들도 인터넷과 책을 허락 없이 학습에 사용해 왔다는 nacs의 비판이 나왔습니다. esafak은 미국 연구소의 학습과 증류가 변형적 이용이라는 논리가 적용된다면 중국 연구소에도 같은 기준을 적용해야 한다고 주장했습니다. jchw는 구매한 토큰에 저작권이 없고 이를 학습해도 파생 저작물이 되지 않으며, 인증 우회나 모델 유출도 없었으므로 최악의 경우 약관 위반이라고 주장했습니다. 이는 해당 댓글의 법적 해석입니다.

반대 의견은 증류보다 수집 방식에 초점을 맞췄습니다. nojito와 villish는 허위 신원, 도난 카드와 API 키를 이용했다는 보고서의 설명을 근거로 삼았습니다. villish는 유럽 연구소가 이런 수집 방식을 합법적으로 쓰기 어려워 경쟁에서 불리해진다는 의견도 덧붙였습니다. qgin은 이용자가 알지 못한 채 다른 모델로 요청을 중계한 점이 공개 자료를 읽는 일과 다르다고 봤습니다. pwinnski는 사용자가 Kimi 가격으로 Claude 응답을 받았다면 실질적인 손해가 있었는지 물었고, DonsDiscountGas는 다른 회사의 모델을 알리지 않고 대체한 사례가 처음이라고 적었습니다.

기술적 개연성에 대한 의문도 있었습니다. realusername과 wren6991은 Kimi의 추론 출력이 Claude와 다르다면 중계 사실을 사용자가 알아챘을 수 있다고 지적했습니다. zahlman은 모델마다 문체가 달라 장기간 숨기기 어렵다고 봤습니다. 반대 방향의 정황으로 KronisLV는 Kimi의 thinking 출력에서 앤트로픽 지침을 본 적이 있다고 했습니다. xscott은 Meta와 Poolside 로컬 모델에서도 비슷한 표현이 나타났다며 그 관찰만으로는 증거가 되지 않는다고 덧붙였습니다.

경제성 논쟁에서는 throwa356262가 DeepSeek이 더 비싼 Claude로 요청을 보낼 이유가 적다고 지적했고, alex_duf는 재판매 계정과 토큰을 이용하는 시장을 고려하면 단가가 달라질 수 있다고 답했습니다. gjm11은 앤트로픽이 주장한 목적이 비용 절감보다 실제 이용자 대화를 모으는 데 있다고 해석했습니다. echelon은 응답 뒤 이용자 행동까지 확인할 수 있어 동기식 중계가 학습에 더 유용할 수 있다고 주장했습니다.

보고서의 동기와 귀속을 의심하는 댓글도 있었습니다. punk_ihaq는 예멘, 러시아, 중국에서 들어온 접속이 실제 행위자의 위치를 뜻하지 않을 수 있다고 지적했습니다. echelon은 보고서를 정부에 “우리가 악성 행위를 막았다”고 보여 주는 메시지로 읽었고, Terretta는 비슷한 시기에 여러 연구소가 보고서를 낸 것을 규제 포획을 위한 로비로 해석했습니다. enraged_camel과 nsoonhui는 중국 모델의 높은 벤치마크 점수와 무단 증류를 연결해 의심했습니다. vopi는 보고서 전체가 증류 자체를 정당한 학습 방법으로 인정하고 있다며, 일부 발췌문만 보고 결론을 내리면 안 된다고 반박했습니다.

## 정리

앤트로픽은 Moonshot과 DeepSeek 등이 Claude의 응답과 추론 기록을 모았다고 주장했고, 자사 서비스를 보호하기 위해 여러 캠페인을 차단했다고 설명합니다. Moonshot 중계가 언제 끝났는지, 대체 계정이나 경로가 남았는지는 보고서만으로 알 수 없습니다. 공개는 그 조사와 앤트로픽의 해석을 알리는 조치였습니다. 이용자 통지와 데이터 처리 관행, 모델 보호, 정책 논의에 영향을 줄 수 있지만 어느 효과를 주된 목표로 삼았는지는 확인되지 않았습니다.

읽을 때는 증거의 범위를 구분해야 합니다. PLA 연계는 앤트로픽의 평가이지 확정된 귀속이 아닙니다. 당시 요청이 앤트로픽 서버에 도달했다는 주장과 미국 정부가 국가 기밀을 입수했다는 주장은 다릅니다. Moonshot이 고객에게 알렸는지도 앤트로픽은 모른다고 했습니다. 보고서는 중요한 조사 결과를 제시하지만, 공개된 범위와 독립적으로 확인된 사실은 별도로 봐야 합니다.
