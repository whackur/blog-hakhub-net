# 미발행 글의 링크 미리보기

미리보기는 링크를 아는 누구나 접근하는 공개 페이지입니다. 인증이나 접근 제어가 아니며 원고도 공개 GitHub 저장소에 남습니다. 비밀정보를 넣지 않습니다. `noindex,nofollow`는 검색 수집기에 대한 요청이며 비공개를 보장하지 않습니다.

## 선택 및 빌드

한·영 원고 `content/korean/blog/<slug>.md`, `content/english/blog/<slug>.md`에 다음 front matter를 지정합니다. 기존 글 작성 규격은 [content-template.md](content-template.md)를 따릅니다.

```yaml
slug: example-draft
translationKey: example-draft
draft: true
unlisted_preview: true
```

`unlisted_preview`는 따옴표 없는 불리언 `true`일 때만 적용합니다. 파일명이 slug이면 `slug`는 생략할 수 있습니다. slug는 소문자 영문·숫자와 단어 사이 하이픈을 사용합니다. 단일 Markdown 파일과 `blog/<slug>/index.md` 번들을 지원하며 두 언어는 각각 선택해야 합니다. 미래 날짜와 만료일이 있는 초안도 미리보기로 확인할 수 있습니다.

```bash
npm ci
npm run build
npm run test:previews
```

Hugo extended(저장소 지정 버전), Go, Node/npm과 Python 3.11 이상이 필요합니다. GitHub Actions도 같은 `npm run build`를 사용합니다. 직접 `hugo`를 실행하면 이 미리보기 합성 단계가 실행되지 않습니다. `npm run dev`는 기존 로컬 초안 확인용입니다.

빌드 출력은 기본 `public/`을 사용합니다. `--destination` 또는 `HUGO_PUBLISHDIR`로 외부 경로를 지정할 때는 새 디렉터리, 빈 디렉터리, 또는 이 빌드가 `.blog-output.json`으로 식별한 기존 출력만 허용합니다. 저장소 내부의 다른 경로, 입력·설정·Git 메타데이터와 겹치는 경로, 심볼릭 링크를 거치는 경로는 거부합니다. 기존 Hugo `public/` 출력은 확인 후 재사용합니다. 검사 도중의 임시 파일은 `TMPDIR`을 따릅니다.

고정 경로는 다음과 같습니다. 중간 구간은 공개된 고정값이며 비밀번호가 아닙니다.

- 한국어: `https://blog.hakhub.net/blog/966685151eac268b47652f9a/<slug>/`
- 영어: `https://blog.hakhub.net/en/blog/966685151eac268b47652f9a/<slug>/`

원고를 수정하고 승인된 배포 절차를 다시 거치면 같은 링크가 갱신됩니다. slug를 바꾸면 링크도 바뀝니다. 일반 `/blog/<slug>/`와 `/en/blog/<slug>/`는 초안 상태에서 생성하지 않습니다.

미리보기의 언어 링크는 선택된 다른 언어 미리보기 또는 실제 프로덕션 출력에 존재하는 번역으로만 연결합니다. 미래 발행·만료·미선택 초안 등으로 번역 출력이 없으면 언어 메뉴는 해당 언어 홈으로 이동하고, 그 번역의 hreflang은 넣지 않습니다. 이미 발행된 일반 글의 언어 전환은 기존대로 동작합니다.

## 수동 Slack 보고

1. 통합 담당자가 검토된 변경을 [기존 발행 절차](workflow.md)에 따라 배포합니다. 미리보기 배포를 위해 `draft: false`로 바꾸지 않습니다.
2. 성공한 Pages 배포의 커밋과 실행 링크를 확인한 후 두 미리보기 URL을 열어 본문, 언어 전환, 스타일을 확인합니다. 개발자 도구에서 `robots=noindex,nofollow`, `referrer=no-referrer`도 확인합니다.
3. 승인된 Slack 대화에 제목, 한·영 URL, 배포 커밋·실행 링크, 검토할 내용을 수동으로 보냅니다. 예: `미발행 검토 요청: <제목> / KO: <URL> / EN: <URL> / 배포: <커밋·실행 링크> / 검토: <요청 내용>`.
4. 같은 링크를 수정했다면 새 배포 완료와 변경 내용을 후속 메시지로 알립니다. Slack 연동이나 자격 증명은 필요하지 않습니다. 자동 링크 카드가 본문을 수집·보관할 수 있으므로 필요한 경우 카드 표시를 해제합니다.

## 정식 발행 및 제거

정식 발행은 별도 콘텐츠 승인을 받은 뒤 양 언어의 `draft`를 `false`로 바꾸고 정상 발행일을 확인합니다. `unlisted_preview`도 제거합니다. 남아 있어도 발행 글에는 적용하지 않습니다. 다음 빌드부터 일반 URL이 생성되고 이전 미리보기 경로는 사라집니다. 미래 발행일의 글은 Hugo의 기존 발행일 규칙을 따릅니다.

미리보기만 내리려면 `draft: true`를 유지한 채 `unlisted_preview`를 제거하거나 `false`로 바꿉니다. 원고 삭제로도 제거됩니다. 매 빌드는 `public/` 전체를 교체하므로 낡은 경로가 남지 않습니다. 배포·브라우저·외부 서비스 캐시나 공개 Git 이력까지 삭제하지는 않습니다.

## 구현과 확인용 데모

빌드 래퍼는 일반 프로덕션 사이트를 먼저 빌드하고, Hugo가 JSON front matter로 변환한 임시 원고 복사본에서 선택한 초안만 렌더링합니다. 전체 초안 빌드를 활성화하지 않습니다. 미리보기는 HTML만 출력하고 목록·사이트맵에서 제외합니다. 별도 빌드의 선택된 페이지 디렉토리와 필요한 정적 자산만 합치므로 홈, 블로그, 분류, 작성자, 관련 글, 이전·다음 글, 검색, RSS, 사이트맵, llms 파일과 일반 페이지의 메타데이터에는 미리보기를 넣지 않습니다. 미리보기에서는 분석·댓글·공유 기능을 끄고 referrer 메타 정책을 적용합니다. 호스팅 계층의 HTTP 헤더를 설정하는 기능은 아닙니다.

`fixtures/draft-previews/`의 한·영 `preview-system-check.md`는 실제 글과 분리된 인프라 데모입니다. 날짜나 기술 기사로 꾸미지 않으며, 위 URL의 `<slug>`를 `preview-system-check`로 바꿔 배포 상태를 확인합니다. 어디에도 목록으로 노출하지 않습니다. 이 파일들의 선택을 해제하거나 삭제하면 데모도 사라집니다.

`npm run test:previews`는 임시 사본에서 실제 프로덕션 명령을 반복 실행해 명시적 선택, 미선택·문자열 값 제외, 미래 날짜, 번들 자원, 언어 전환, 검색·피드·사이트맵·llms·공유 자산 누출, 정식 발행, 선택 해제와 삭제 후 경로 제거를 검사합니다. 실제 원고·이미지는 수정하지 않습니다. 라이브 확인과 독립 리뷰는 배포 담당자가 수행합니다.
